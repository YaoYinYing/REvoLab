## Human review round 1 (REQUEST CHANGES) — findings and resolutions

1. **Status/authority language** — removed all premature `Accepted`/`COMPLETE`/`approved`;
   every doc + `IMPLEMENTATION_STATE.md` now reads **Proposed — pending human review**.
2. **Global resource vs project scope** — one relational answer: `ScientificObject`/all
   reference nodes/provenance Relations are **global** (no `project_id`); `Evidence`/
   `Decision` are **project-scoped**; `Project`/membership/annotation are project-local.
   Definite Project-deletion sequence added.
3. **Object identity vs revision identity** — split conceptual `series_id` from immutable
   `revision_id`; each content revision is an immutable record with its own UUID and
   provenance edges address `revision_id`.
4. **Canonical edge matrix** — single source|type|target|cardinality|immutable matrix;
   fixed the `produced`/`imported_as`/`evaluates` direction contradictions everywhere.
5. **Evidence double-expression** — `polarity` is a field on Evidence (source + target +
   claim); `supports`/`contradicts` are no longer separate graph edges.
6. **Logical vs physical Relation** — freeze only the logical graph contract; the physical
   Relation schema (polymorphic table vs edge-family tables) is deferred to the Phase-1 spike.
7. **Relation uniqueness vs append-only** — also deferred to the spike with a default
   (independent relation identity + supersession).
8. **Authority vs resolver/provider** — external identity is `(authority, native_id)`;
   resolver (OpenBio etc.) never changes durable identity.
9. **Actor-contextual availability** — `available(actor, provider) = READY ∧ creds(actor)
   ∧ project policy`, never stored; credentials keyed per `(actor_id, provider_key, kind)`.
10. **Promotion narrowed** — ALL persistence is a typed domain operation; the promotion
    gate applies ONLY to `Decision draft → committed`.
11. **Lifecycle/API unified** — Decision status = exactly `draft | committed` (+ derived
    `superseded`); Relations immutable (no `PATCH /relations`); Evidence `PATCH` limited to
    interpretive fields.
12. **Checksum vs origin** — checksum proves content integrity; origin comes from the
    provenance assertion + provider identity.
13. **CLAUDE.md / Ralph** — restored the short Engineering principles; Ralph is only used
    when explicitly requested (never a fixed mandatory step).

## Human review round 2 (REQUEST CHANGES, second round) — findings and resolutions

A second human review again returned **REQUEST CHANGES** (still ~80–85% of direction
right, "don't merge yet"). All of its findings have now converged on this branch:

1. **Project-scoped authorization projection** — global identity != global readability.
   Visibility is a computed per-query projection `Actor → ProjectMembership →
   ProjectResourceLink → visible resource → visible provenance edge` (an edge appears only
   when all endpoints are visible); never a stored per-object ACL. `ProjectObjectMembership`
   is renamed **`ProjectResourceLink`** (`resource_kind` constrains global categories).
   Written into `ADR-0008` and `COLLABORATION_IDENTITY.md`.
2. **SQL-valid Project deletion** — a Project is **tombstoned** with `deleted_at`
   (never hard-deleted, keeping FKs valid); active membership links are hard-deleted;
   `Evidence`/`Decision` are archived; global resources (objects, relations, references)
   are left untouched.
3. **`SCIENTIFIC_GRAPH.md` is the single source of graph truth** — the wire value is
   standardized to `consumed_as_input_by` (no more `consumed_input_by`); the
   SYSTEM_ARCHITECTURE knowledge-graph direction is fixed; IMPLEMENTATION_ROADMAP no longer
   carries the stale `UNIQUE(project,…)` or a "Generic Relation target type: Decided"
   claim — physical relation shape is deferred to the Phase-1 spike and Roadmap only
   references `SCIENTIFIC_GRAPH.md`.
4. **Frozen Evidence association contract** — legal `Evidence.source` kinds (incl.
   experiment/note as source) and `Evidence.target` kinds, exactly one of each, 1:1
   cardinality, and `source`/`target` immutable once written.
5. **One canonical dependency DAG** — `A --> B` means "A imports/consumes B's public
   contract"; the same acyclic DAG is shared verbatim by `DOMAIN_BOUNDARIES.md` and
   `SYSTEM_ARCHITECTURE.md`. Project is a member/participant (links global resources via
   the Identity contract); Provider owns providers/drivers/capabilities/schemas and no
   longer owns credentials/tools (credentials live in the credential store).
6. **Provider health split from actor availability** — `ProviderRuntimeHealth`
   (`READY|DEGRADED|UNREACHABLE`, per-provider, actor-independent, lazily probed) is a
   distinct coeffect from `CapabilityAvailability(actor,project)`
   (`AVAILABLE|CREDENTIAL_MISSING|NOT_AUTHORIZED|PROVIDER_UNAVAILABLE`, which is **derived,
   never stored**). `credential_missing` is never a provider property. (`ADR-0012`,
   `PROVIDER_CAPABILITIES.md`.)
7. **Harness step 7 = INDEPENDENT REVIEW** — the fixed 7th phase is a plain fresh reviewer
   by default; **Ralph only on explicit human request** (never a mandatory fixed step).
   (`HARNESS_OPERATING_MODEL.md`, aligned with the `engineering-workflow` skill.)
8. **Container-engine safety guardrails** — Docker/Podman access is a **privileged external
   capability, not a workspace write**; only the known repo `docker-compose.yml` for local
   postgres, with no `--privileged`, no host PID/IPC, no `docker.sock` mount, no bind outside
   the approved root, approval required to invoke host Docker/Podman; a subagent/sandbox is
   never a safe proxy for the daemon. (`HARNESS_OPERATING_MODEL.md` safety plane + `CLAUDE.md`.)
9. **Frozen ScientificObject nomenclature** — `ScientificObjectSeries.id` (`series_id`) and
   `ScientificObjectRevision.id` (`revision_id`); the ambiguous `ScientificObject.id` (meant
   as both) is removed everywhere. (`SCIENTIFIC_OBJECT_MODEL.md`, `ADR-0009`, etc.)
10. **Skill list matches reality** — `.agents/skills/` now actually contains the documented
    constitutional skills `architecture-review` and `security-boundaries` (added), so the
    AGENT_CONTEXT + Harness skill lists match the real tree (11 skills total).
11. **IMPLEMENTATION_STATE verified items** — clean dependency installation and full hosted
    CI moved from "Not yet verified" to verified (GHA is green on the PR head).
12. **Deleted the 5 superseded pointer files** — `overview.md`, `domain-model.md`,
    `drivers.md`, `evidence-and-lineage.md`, `agent-and-skills.md` are gone and referenced
    nowhere.

A fresh independent architecture review pass (the `architecture-review` skill) has been run
against this converged state; its findings are folded in. Status remains **PROPOSED —
pending human review**.
